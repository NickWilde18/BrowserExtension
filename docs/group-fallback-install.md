将新 ZIP 解压到一个新的空目录，确认该目录根部有 `manifest.json`。在浏览器扩展管理页启用开发者模式，加载该目录；如果已有相同 ID 的开发者扩展，按浏览器要求切换到新目录或重新加载，再确认没有同时运行两份。不要覆盖旧目录，以便回退。

Mac Arc 尚未实测。建议在原先复现的同一 Mac 上完成以下验收：

1. 同一浏览器配置中登录平台，确认插件连上。让助手打开一个已明确允许的测试网页，确认分组未及时可用时仍能实际导航，不能只看到空白标签。
2. 让助手读取该页一个临时加入的非敏感标记；核对工具结果与最终回答确实来自当前页面。
3. 新建第二个标签并列出；另一个对话不能访问本对话的标签。
4. 普通标签关闭后，不再出现在本对话列表。若浏览器原生分组可用，拖出助手创建的 AI 组仍撤销该页控制。
5. 让助手等待用户确认时，停止本轮，确认窗口关闭、调试附着释放；随后新一轮仍能正常使用浏览器。工具栏「停止」会全局暂停，需点「恢复」才继续。
6. 正常结束、失败或超时后，平台连接与网页仍在，调试提示条应随本轮全部附着释放而消失；不要把保留网页归属误认为未停止该轮。

出现失败时保留：具体动作、发生时间、是否仍为空白页、工具错误码、插件连接状态、分组调用是否超过等待预算。不要在日志或截图中包含凭据及私人网页内容。Linux Chromium 的测试记录不能替代本表的 Mac 真机验收。
